## 原因与证据

1. 本机 App `/health` 返回 200，数据库 SELECT 1 正常；主题 Home/Programs 也为 200。
2. 原 Cloudflare Quick Tunnel 域名 `subscribers-cheaper-crm-encyclopedia.trycloudflare.com` 无法解析（ENOTFOUND）。Shopify 两个本地预览的 App Proxy 返回 500 HTML，包含 “There was an error in the third-party application”，新请求没有到达 App 路由日志。
3. 普通 App dev 重启后，新的临时域名返回 Cloudflare 530 / error 1033，cloudflared 子进程已经退出。1033 表示 Cloudflare 找不到健康隧道连接。现有日志不足以确定最初退出究竟由休眠、网络切换还是进程异常引起，不把任一猜测当已证实原因。
4. 对已核实的 Shopify Booking 代理端口 50538 建立独立 HTTP2/IPv4 Quick Tunnel，保留 info 级诊断日志，确认注册成功后通过 Shopify 官方 `app dev --tunnel-url` 切换开发配置。公网健康检查与真实 App Proxy 随后均恢复。

结论：故障发生于 Shopify → 本机的开发隧道连接，不是已证实的课表 SQL、预约数据或业务校验错误。HTTP2 恢复通过不等于已证明 UDP 被防火墙封锁。临时隧道仍不提供持续运行保证。

官方依据：[Shopify 开发网络选项](https://shopify.dev/docs/apps/build/cli-for-apps/networking-options)、[Cloudflare 1033](https://developers.cloudflare.com/support/troubleshooting/http-status-codes/cloudflare-1xxx-errors/error-1033/)、[HTTP2/IPv4 参数](https://developers.cloudflare.com/tunnel/advanced/run-parameters/)。
